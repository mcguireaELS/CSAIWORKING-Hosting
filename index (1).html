01What hosting means

A file travels. A hosted page has an address

If you email it or use SharePoint

  • Everyone ends up with their own copy. Change it and you have to send it again and hope people open the new one.
  • SharePoint usually just downloads the file instead of opening it as a page.
  • If the person does not have the company fonts installed, they see a converted version, not the branded one.
  • It sits behind our login, so you cannot give it to a customer.

If you host it

  • There is one copy. Change it and the link everyone already has shows the new version.
  • It opens as a real page, in any browser, on any device, with nothing to download.
  • The fonts sit next to the page, so everyone sees the real Tiempos and National 2.
  • It is a normal web address, so you can share it with anyone, inside or outside Elsevier.

Email and SharePoint move a file around. Hosting gives the thing a home and a front door.

02What you could host

So what would you actually put on it

Customer facing

  • Self service onboarding for accounts with no dedicated CSM
  • Getting started walkthroughs for a new feature, sent as one link
  • Release highlights, as a page instead of a wall of email
  • Quick reference guides, decision trees, and value calculators

Internal

  • Playbooks and process guides, one link per workflow
  • New hire and new CSM onboarding hubs
  • A shared library of prompts the group has vetted
  • A team index linking everything we host

Start with the ones you can measure. Anything you can instrument tells you what people actually did

03What is Git

First, what Git actually is

Git is a free, open-source distributed version control system designed to track changes in source code during software development. It acts like a time machine for your files, allowing you to save snapshots of your project, revert to older versions, and collaborate with other developers without overwriting each other's work.

04Why GitHub

The tool we already had, and its honest catch

  • We already have access. No new tool, no license request, no procurement. And GitHub Pages hosting is free.
  • The catch: it is built for developers. No friendly publish button. It talks in repositories, commits and branches. First time through, it is genuinely confusing.
  • How I got past it. I did not become an expert. Claude knew the current, correct steps and translated the clunky interface into plain instructions: make the repo, add the file, turn on Pages, copy the link.

Lean into what Claude does well. Hand it the capable but awkward tool, and use each for its strength.

05Why it matters for us

The pattern, not the product

  • Build in Claude → host on GitHub Pages → share one link → measure use.
  • That turns "I made a cool thing in Claude" into "I shipped something people can use, and learn from."
  • Low lift. With a template, a new one is about a two minute setup.
